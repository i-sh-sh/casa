## מה זה עושה

**כסף.** תקציב מעטפות בסגנון YNAB: כל שקל מקבל ייעוד לפני שמוציאים אותו, והיתרות
מתגלגלות בין חודשים — ₪250 לביטוח רכב כל חודש הופכים ל-₪2,750 בחודש שהחיוב מגיע,
במקום להיראות כמו אסון. בנוסף: מי שילם על מה, ומי חייב למי — עם כפתור שסוגר את
החשבון בלי להמציא הוצאה חדשה.

**מזווה.** מלאי לפי אצוות, עם תאריכי תפוגה שמחושבים לבד. צריכה יורדת מהאצווה שפגה
ראשונה, כדי לא לזרוק אוכל שיטתית.

**קניות.** כשמוצר יורד מתחת לכמות המינימלית שהגדרנו לו, הוא נכנס לרשימה **לבד**.
הרשימה ממוינת בסדר ההליכה בסופר. סימון «נקנה» מחזיר את המוצר למזווה באותה לחיצה.

## הקמה מאפס

### 1. מסד נתונים

ב-Vercel: **Storage → Neon Serverless Postgres**, אזור **Frankfurt (eu-central-1)**.
ודאו ש-`DATABASE_URL` מכיל את כתובת ה-**pooler** (שם המארח מכיל `-pooler`) — קריטי
לסביבה serverless כדי לא למצות חיבורים.

### 2. משתני סביבה

ב-Vercel תחת **Settings → Environment Variables**, ואז **Redeploy**:

| משתנה | חובה? | תפקיד |
|---|---|---|
| `DATABASE_URL` | ✅ | נוצר אוטומטית בחיבור Neon |
| `JWT_SECRET` | ✅ | 32 בתים אקראיים שחותמים את הסשן. בלעדיו **אף אחד לא יכול להיכנס**. `openssl rand -base64 32` |
| `GOOGLE_CLIENT_ID` | ✅ | מזהה הלקוח של Google Sign-In — הדרך היחידה להיכנס |
| `CRON_SECRET` | מומלץ | מגן על הקרון היומי (`/api/cron/daily`) |
| `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` | אופציונלי | התראות יומיות בטלגרם |
| `VAPID_PUBLIC_KEY` + `VAPID_PRIVATE_KEY` + `VAPID_SUBJECT` | אופציונלי | Web Push. `npx web-push generate-vapid-keys` |

בלי מפתחות ההתראות המערכת פשוט שקטה — זו לא שגיאה.

### 3. Google Sign-In

ב-[Google Cloud Console](https://console.cloud.google.com/apis/credentials): **Create
Credentials → OAuth client ID → Web application**. תחת *Authorized JavaScript origins*
הוסיפו את כתובת הפרודקשן ואת `http://localhost:5173`. העתיקו את ה-Client ID
ל-`GOOGLE_CLIENT_ID`.

### 4. הרצה ראשונה — לפי הסדר הזה

> ⚠️ **ביצה ותרנגולת:** הכניסה דורשת את טבלת `users`, שהמיגרציה יוצרת — אבל כפתור
> המיגרציה דורש כניסה. בפריסה חדשה לגמרי הריצו את `db/schema.sql` פעם אחת ישירות
> מקונסולת Neon. אחרי שיש בעל בית אחד, הכפתור מטפל בכל השאר.

1. הריצו את `db/schema.sql` בקונסולת Neon.
2. היכנסו לאתר והתחברו בגוגל — **הנכנס הראשון הופך אוטומטית לבעל הבית**.
3. **הגדרות ← מסד הנתונים ← «זריעת קטגוריות ומוצרי ברירת מחדל»** — 27 קטגוריות
   ישראליות ו-15 מוצרי יסוד, כדי שהמסך הראשון לא יהיה ריק.
4. **הגדרות ← חשבונות** — עדכנו את יתרת הפתיחה של «עובר ושב».
5. **תקציב ← «מילוי החודש לפי היעדים»**.

כל מי שנכנס אחריכם ממתין לאישור שלכם ב**הגדרות ← מי בבית**.

## פיתוח

```bash
npm install
npm run dev          # Vite על :5173, מפנה /api ל-:3000
npx vercel dev       # הפונקציות, על :3000

npm test             # 42 בדיקות על הלוגיקה הטהורה
npm run typecheck    # שרת ולקוח בנפרד
npm run check        # הכול, כמו ב-CI
```

אחרי כל שינוי ב-`db/schema.sql` הריצו **`npm run schema:build`** ו-commit לשני
הקבצים. `db/schema.ts` הוא מה שהמיגרציה מייבאת בפועל (פונקציית Vercel אורזת רק מה
שהקוד מפנה אליו סטטית), ובדיקה נופלת אם השניים מתפצלים.

## מבנה

```
api/           פונקציות Vercel — ראוטר אחד למודול (תקרת 12 פונקציות)
  _lib/        db, auth, http, router, validate, notify
db/            schema.sql (מקור האמת) + schema.ts (נגזר, בשביל המיגרציה)
shared/        הלוגיקה הטהורה — money.ts, pantry.ts, types.ts. משותפת לשרת וללקוח
src/           React: app/, lib/, ui/, features/
scripts/tests/ בדיקות על shared/ ועל הסכימה
```

`shared/` הוא הלב: כל חישוב שאפשר לבדוק בלי מסד נתונים יושב שם, ולכן נבדק. ה-API
שואל את מסד הנתונים ומעביר את התוצאה דרכו; ה-UI מרנדר את מה שחוזר.
