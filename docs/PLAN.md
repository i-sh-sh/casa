# קאסה — התוכנית

מערכת ניהול בית לשנינו. לא אפליקציה גנרית שהורדנו, ולא רשימת מטלות בפתקים —
מערכת שיודעת מה יש בבית, כמה כסף יש, מה נגמר, ומה צריך לשלם השבוע.

התוכנית הזאת היא מסמך חי. מה שנבנה כבר מסומן, ומה שלא — מסודר לפי הסדר שבו
נבנה אותו.

---

## העיקרון שמנחה הכול

> **מערכת שדורשת עבודה כדי להישאר מעודכנת — לא תישאר מעודכנת.**

זה לא סיסמה, זו החלטת תכנון שחוזרת בכל פיצ׳ר:

* רשימת הקניות **נכתבת לבד** כשמשהו במזווה יורד מתחת למינימום. לא צריך לזכור.
* סימון פריט כ«נקנה» **מכניס אותו למזווה** באותה לחיצה. אין הזנה כפולה.
* תפוגה **מחושבת לבד** מ«ימי מדף» של המוצר. אף אחד לא מחשב «היום ועוד תשעה ימים».
* קנייה שלמה נרשמת בתקציב כ**שורה אחת**, לא ארבעים שורות של ₪3.90.

כל פעם שנתלבט על פיצ׳ר, השאלה היא: *כמה עבודה ידנית הוא מוסיף, וכמה הוא חוסך.*

---

## ממה העתקנו, ולמה דווקא משם

לא המצאנו מודלים. לכל מודול בחרנו מערכת שכבר הוכיחה את עצמה, וגנבנו ממנה את
הרעיון המרכזי — לא את הממשק.

| המערכת | מה לקחנו | למה זה עובד |
|---|---|---|
| **[Grocy](https://grocy.info)** | מלאי לפי אצוות + `min_qty` שמייצר רשימת קניות | הופך מלאי מ*מטלה* ל*שירות*. זה הרעיון היחיד שמצדיק לנהל מזווה בכלל |
| **YNAB** | תקציב מעטפות עם גלגול יתרות | עונה על «כמה מותר לי להוציא על זה» — השאלה היחידה שמשנה החלטה בקופה |
| **Splitwise** | `paid_by` נפרד ממי שרשם, ו«סגירת חשבון» | בלי זה יודעים כמה הבית הוציא ולא יודעים מי בחיסרון |
| **Tody / Sweepy** | ניקיון כ*הצטברות לכלוך*, לא כדדליין | מטלה שחוזרת כל שבוע ומופיעה באדום ביום שלישי — נהפכת לרעש שמתעלמים ממנו |
| **Mealie / Paprika** | מתכון → תפריט שבועי → רשימת קניות | הדרך היחידה שבה תכנון ארוחות שורד יותר משבועיים |
| **HomeBox / Centriq** | רכוש עם אחריות, קבלה, ותאריך שירות | «מתי קנינו את המקרר ומתי נגמרת האחריות» — שאלה שנשאלת פעם בשנתיים ואין לה תשובה |
| **Cozi** | לוח שנה משפחתי משותף | האירוע שאחד יודע עליו והשני לא הוא מקור חיכוך קבוע |

ומה שכבר הוכח **אצלנו**, במערכת החתונה: כניסה בגוגל עם תפקידים, הוצאות עם
תשלומים ולוג, רשימה משותפת, משימות עם תזכורות, פוש לנייד, ובוט טלגרם שעונה על
שאלות בלי לפתוח דשבורד. הרעיונות עברו לכאן; הקוד נכתב מחדש ונקי.

## שלב 1 — הבסיס ✅ *(נבנה)*

### כסף — תקציב מעטפות
- [x] חשבונות (בנק / מזומן / אשראי / חיסכון) עם יתרה **מחושבת**, לא שמורה
- [x] קטגוריות בקבוצות, עם יעד חודשי
- [x] הקצאה חודשית לכל מעטפה, עם **גלגול יתרות** — ₪250 לביטוח כל חודש הופכים ל־₪2,750 בחודש שהחיוב מגיע
- [x] חריגה מתגלגלת גם היא, במכוון: אם חרגנו, המעטפה נשארת במינוס עד שמישהו יעביר לשם כסף
- [x] «ממתין לייעוד» — כמה כסף נכנס ועוד לא קיבל תפקיד
- [x] תנועות: הוצאה, הכנסה, העברה בין חשבונות (שתי שורות, בלי קטגוריה)
- [x] «מילוי החודש לפי היעדים» — לחיצה אחת, בלי לדרוס מה שהוקצה ביד
- [x] חשבונות קבועים (ארנונה, ועד בית, ביטוח) עם תאריך חיוב שמתקדם לבד. חיוב ב-31 לא בורח למרץ
- [x] **איזון בינינו** — מי שילם, מי בחיסרון, וכפתור «סגירה» שלא ממציא הוצאה חדשה
- [x] הוצאה «אישית» לא נכנסת לאיזון בכלל

### מזווה + קניות
- [x] מוצרים עם יחידה, מדף, מיקום, וכמות מינימלית
- [x] מלאי **לפי אצוות** — שני קרטוני חלב מאותו שבוע פגים בתאריכים שונים
- [x] תפוגה מחושבת מ«ימי מדף» כשלא הוזנה ידנית
- [x] צריכה יורדת מהאצווה **שפגה ראשונה** (FEFO) — הדרך היחידה שלא זורקת אוכל שיטתית
- [x] צריכה של יותר ממה שיש **מותרת**, ומדווחת על הפער. סירוב היה מלמד אותנו להפסיק לרשום
- [x] רשימת קניות **שנולדת מהמלאי**, פעם אחת לפריט (אינדקס ייחודי חלקי, לא בדיקה ותקווה)
- [x] סימון «נקנה» מכניס למזווה אוטומטית
- [x] הרשימה ממוינת **בסדר ההליכה בסופר**, לא בסדר ההקלדה
- [x] «סיום קנייה» — סוגר את הסל ורושם שורה אחת בתקציב

### תשתית
- [x] כניסה בגוגל בלבד. הנכנס הראשון = בעל הבית, כל השאר ממתינים לאישור
- [x] תפקידים: בעל הבית / שותף / צופה / ממתין
- [x] מיגרציה אידמפוטנטית בלחיצת כפתור + בדיקת «הסכימה מעודכנת?»
- [x] זריעת ברירת מחדל ישראלית — 27 קטגוריות, 15 מוצרי יסוד
- [x] קרון יומי: מרענן את הרשימה, ומתריע על תפוגות וחשבונות. **לא** מתריע על מה שכבר פג — אי אפשר לפעול על זה
- [x] טלגרם + Web Push, שניהם אופציונליים. בלי מפתחות המערכת פשוט שקטה
- [x] 42 בדיקות על הלוגיקה הטהורה + שומר סחף בין הסכימה למיגרציה

## שלב 2 — מה שמכאיב הכי מהר אחרי זה

### מטלות ותחזוקת בית
המודל של **Tody**, לא של Todoist. מטלה לא «באיחור» — היא *מתלכלכת*.

- [ ] מטלה עם מחזוריות (כל X ימים) ומצב «נקיון» שדועך עם הזמן
- [ ] מסך אחד שמסודר לפי *כמה דחוף*, לא לפי תאריך
- [ ] חלוקה בינינו + «מי עשה מה לאחרונה»
- [ ] תחזוקה שנתית: טסט, ביטוח רכב, מסנן מים, ניקוי מזגן, בדיקת גז
- [ ] התראה אחת, בזמן שאפשר לפעול בו

### קבלות ואחריות
- [ ] צילום קבלה מהנייד, מחובר לתנועה בתקציב
- [ ] אחריות עם תאריך תפוגה והתראה חודש לפני
- [ ] «איפה קנינו את זה ומתי» — לרהיטים, מכשירים, כלים

### הרשימה שלומדת
- [ ] «בדרך כלל קונים חלב כל 5 ימים» — הצעה לפני שנגמר, מתוך `stock_log`
- [ ] מחיר אחרון לפריט, וסך משוער לעגלה לפני שיוצאים
- [ ] רשימות לפי חנות (סופר / פארם / שוק)

## ההחלטות שכבר נסגרו

| החלטה | הבחירה | למה |
|---|---|---|
| ריפו | חדש (`casa`), נפרד מ-`wedding` | מערכת אחרת, מחזור חיים אחר, נתונים אחרים |
| צד קדמי | React + Vite + TypeScript | 20 מסכים קדימה. TS תופס באגים לפני שהם מגיעים לנייד |
| צד שרת | Vercel Functions + Neon Postgres | מוכח אצלנו, חינם בקנה מידה הזה |
| כניסה | גוגל בלבד | סיסמה משותפת היא דליפה אחת מלהיות של כולם |
| כסף | `NUMERIC(12,2)`, לעולם לא float | ₪0.00 שלא מתאפס הוא באג שנראה כמו שגיאת חישוב |
| מחיקה | רכה (`deleted_at`), לא `DELETE` | בחודש הבא, כשמעטפה לא מסתדרת, «מה נמחק כאן» חייב תשובה |
| ריבוי משתמשים | טבלת `users` עם תפקידים, בלי `household_id` | פתוח לאנשים נוספים, סגור למשקי בית נוספים |
