# מערכת הגרסאות

הועברה ממערכת החתונה, עם הבדל אחד מהותי: שם הגרסה הוטבעה ידנית בכל עמוד HTML,
וכאן היא **מוזרקת בזמן בנייה** מ־`package.json`. פחות קובץ לתחזק, ואי אפשר
לשחרר עמוד שנושא מספר ישן.

---

## מה זה פותר

לשונית שנפתחה בבוקר ונשארה פתוחה עד הערב מריצה קוד ישן. היא תיראה תקינה
לחלוטין, ותיפול על עמודה שהמיגרציה הוסיפה אחר הצהריים. מערכת הגרסאות היא מה
שגורם ללשונית הזאת **לדעת שהיא מיושנת** ולעשות עם זה משהו.

שני מסלולים:

| מסלול | מתי | מה קורה |
|---|---|---|
| **רך** | ברירת מחדל לכל שחרור | הלשונית מתרעננת לבד ברגע שאף אחד לא באמצע משהו |
| **קשיח** | `--mandatory`, או בנייה מתחת ל־`min_version` | ריענון מיידי עם ניקוי מטמון; אחרי שני ניסיונות כושלים — דיאלוג |

**ההבדל בין `mandatory` ל־`min_version` הוא העיקר.** `mandatory` תופס את מי
שנמצא מחובר בזמן השחרור הספציפי. `min_version` מרים את הרצפה ותופס **כל**
לשונית ישנה שקיימת, כולל זו שפתוחה מאז מרץ.

---

## מה כבר עובד ✅

| קובץ | תפקיד |
|---|---|
| `shared/version.ts` | השוואת גרסאות והחלטת העדכון — לוגיקה טהורה, 18 בדיקות |
| `public/version.json` | המניפסט שכל לשונית מושכת |
| `scripts/release.ts` | כלי השחרור — כותב גרסה ל־3 קבצים |
| `vite.config.ts` | מזריק `__APP_VERSION__` מ־`package.json` בזמן בנייה |
| `src/lib/version.ts` | הריצה: פולינג, מסלול רך, מסלול קשיח, תקרת ניסיונות |
| `src/ui/kit.tsx` | `markBusy` — גיליון פתוח או טופס בשליחה חוסמים ריענון רך |
| `src/app/App.tsx` | דיאלוג «העדכון לא נתפס» |
| `src/features/settings/SettingsScreen.tsx` | כרטיס «גרסה» |

### איך משחררים

```bash
npm run release patch                    # 0.1.0 → 0.1.1
npm run release minor --notes "מה השתנה"
npm run release 1.0.0 --mandatory        # כל לשונית פתוחה תתרענן מיד
npm run release 1.0.0 --min same         # מרים את הרצפה: כל בנייה ישנה נחסמת
npm run release patch --dry-run          # מראה מה ישתנה, לא כותב
```

ואז `git commit` + `git push`. **שום דבר לא נכנס לתוקף עד הפריסה** — המניפסט
הוא קובץ סטטי, אז «לכפות עדכון» פירושו לשחרר בנייה שאומרת את זה.

בדיקה נופלת אם `package.json` ו־`version.json` לא מסכימים, אז אי אפשר לשכוח.

## מה נשאר לעשות

לפי סדר תועלת. כל משימה עומדת בפני עצמה.

### 1. Service Worker — ⬜ הפער האמיתי היחיד

לקאסה אין SW בכלל, כלומר **אין עבודה אופליין** — וזה כואב בדיוק במקום הכי
חשוב: רשימת הקניות בסופר, שם הקליטה גרועה.

**קבצים:** `public/sw.js` (חדש), `index.html`, `scripts/release.ts`

1. `public/sw.js` עם `const CACHE_NAME = 'casa-v0.1.0';`
   אסטרטגיה: **network-first** לניווט ול־`/api/*`, **cache-first** ל־`/assets/*`
   (הם ממילא בעלי hash בשם, אז הם אף פעם לא מתיישנים).
   ב־`activate` — למחוק כל מטמון ששמו אינו `CACHE_NAME` הנוכחי.
2. רישום ב־`src/main.tsx`, מאחורי `if ('serviceWorker' in navigator)`.
3. ב־`scripts/release.ts` להוסיף לרשימת ה־`edits`:
   ```ts
   replaceIn(SW, /(const CACHE_NAME = ')[^']*(')/, `$1casa-v${next}$2`)
   ```
   **זה הצעד הקריטי.** בלעדיו מטמון ישן שורד שחרור, והעדכון הקשיח לא באמת
   מעדכן — הוא טוען מחדש את אותם קבצים.
4. בדיקה ב־`scripts/tests/version.test.ts`: `CACHE_NAME` ב־`sw.js` מכיל את
   הגרסה שב־`package.json`. באותו דפוס של הבדיקה שכבר קיימת שם.

> ⚠️ SW הוא הדבר הכי קל לירות בו ברגל: SW תקוע מגיש בנייה ישנה לנצח. אל
> תעשו cache-first ל־`index.html` בשום מצב.

### 2. בדיקה ידנית של המסלול הקשיח — ⬜ 10 דקות, שווה כל שנייה

זה המסלול שאם הוא שבור, הוא נועל את המערכת. הלוגיקה בדוקה ביחידות; מה שלא
נבדק הוא ההתנהגות בדפדפן אמיתי.

1. פרסו, פתחו את האתר, השאירו לשונית פתוחה.
2. `npm run release patch --mandatory --notes "בדיקה"` → commit → push.
3. תוך דקה הלשונית אמורה להתרענן לבד.
4. **את מקרה ה«תקוע»:** ערכו ידנית את `public/version.json` בפרודקשן לגרסה
   שלא קיימת (למשל `9.9.9`) עם `"mandatory": true`. הלשונית תנסה פעמיים ואז
   תציג את הדיאלוג. **ודאו שהיא לא בלולאת ריענון אינסופית.**
5. החזירו את `version.json` למצבו.

### 3. הודעת טלגרם על שחרור — ⬜ נחמד שיהיה

`api/cron/daily.ts` כבר יודע לשלוח. אפשר להוסיף ל־`api/admin/[...path].ts`
מסלול שקורא את `version.json` ושולח את ה־`notes` — או פשוט לקרוא לזה מ־CI
אחרי פריסה מוצלחת.

### 4. היסטוריית שחרורים — ⬜ אם יתחשק

כרגע `notes` מחזיק רק את השחרור האחרון. אפשר להוסיף `public/releases.json`
שכלי השחרור **מוסיף** אליו, ולהציג אותו בכרטיס «גרסה» כרשימה נגללת.

## מלכודות שכבר טופלו

אלה נפתרו בקוד; מתועדות כאן כדי שלא «יתוקנו» בחזרה.

- **השוואה מספרית ולא טקסטואלית.** `"1.10.0" < "1.9.9"` בהשוואת מחרוזות,
  והשחרור העשירי היה נראה ישן מהתשיעי. כל לשונית הייתה מפסיקה להתעדכן.
- **בנייה שלא יודעת את הגרסה שלה לא נחסמת לעולם.** זה המצב שאליו נופלת
  בנייה עם הגדרה שגויה, וחסימה שלה הייתה נועלת את הבית מחוץ לתקציב שלו.
- **בנייה שקדימה מהמניפסט לא נוגעים בה.** פריסת Preview חדשה מהפרודקשן;
  ריענון היה מחזיר את הבודק לגרסה הישנה, שוב ושוב.
- **תקרת שני ניסיונות לריענון כפוי**, נספרת ב־`sessionStorage` לפי גרסת יעד.
  בלעדיה, פריסה חצי־גמורה = לולאת ריענון אינסופית שהופכת את הטלפון ללא שמיש.
- **פולר יחיד לכל האפליקציה.** ההוק נקרא בשני מקומות; שני פולרים היו מכפילים
  את מונה הניסיונות, והתקרה הייתה נשרפת אחרי ניסיון אמיתי אחד.
- **`min_version` לא יכול להיות חדש מהשחרור.** אחרת כל לשונית נחסמת ואין
  לאן לשדרג.
- **אי אפשר לרדת בגרסה.** לשונית שחושבת שהיא קדימה לא מתעדכנת יותר לעולם.
- **המניפסט נמשך עם `?t=` ולא רק `no-store`.** CDN שמחזיק מניפסט ישן חמש
  דקות מנטרל את כל המנגנון בשקט.
